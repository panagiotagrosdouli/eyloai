## Canonical data and publication boundaries

- Private collections, practice, interviews, task plans, briefs, method/ethics plans, conference records and private forms live under existing `projects.data.product_workbench`. Spreadsheet data uses `projects.data.spreadsheet`. Project compare-and-set, explicit saves and conflict comparison remain authoritative. No competing Notes, Life, learning or AI-memory database is created.
- Memory reads canonical Notes/projects/EYRA messages. Studio and reviewed translations create canonical Notes. Task workflows create canonical `life_tasks`; conference deadlines create canonical `calendar_events`. Calendar records currently use UTC midnight-to-midnight with an all_day flag; the older Calendar UI renders localized start times, so complete all-day/timezone UX remains open.
- New additive collaboration contracts are `eylo_directory`, `eylo_teams`, `eylo_team_invites`, `eylo_team_members`, `eylo_connections`, `eylo_community_posts`, `eylo_peer_submissions`, `eylo_peer_reviews`, `eylo_feedback` and `eylo_api_tokens`. Source inventory found no existing canonical team/connection/review/feedback/token tables; existing institution memberships are preserved for their separate institution scope.
- Directory name/bio publication is deliberate and visible to signed-in users. Community publication is separately confirmed and visible to signed-in users. A connection requires both users' consent. Team membership never grants access to private projects, Notes or file bytes.
- Peer Review shares only the title/text snapshot explicitly confirmed by its author, to an accepted connection. Reviewer drafts are private to the reviewer; submitted reviews become visible to the author and cannot be edited. Withdrawing a submission removes its attached reviews, with confirmation.
- Existing Settings export v2 still covers its30 canonical collections. New collaboration pages export only the user's loaded authored records (up to1000 visible recent rows per collection); this is not a complete DSAR or collaboration archive. API secrets are never included. Full privacy/account deletion, processor/backups and Storage cleanup acceptance remain open.

## Security and resource boundaries

All new tables enable RLS, revoke anonymous access and grant only required columns. Ownership/recipient/team-role conditions govern reads and writes. Team join consumes an accepted invite inside the membership transaction; a removed member cannot reuse it. Invites expire after7 days and the original inviter must still hold authority.

Private boolean helpers use fixed empty search paths and expose only the caller's authorization. They use SECURITY DEFINER only for membership recursion avoidance or privileged Auth metadata/session reads; public/anonymous execution is revoked. The invite-consumption trigger cannot be called directly by clients. Administrator access checks current `auth.users.raw_app_meta_data`, an active matching `auth.sessions` row and account ban state. User metadata and stale JWT role claims alone do not grant authority. Existing ordinary owner-only contracts retain their prior JWT semantics; hosted session/deletion acceptance is still required.

The developer credential lookup is service-only and returns scoped active-token metadata after checking expiry, revocation and account ban state. Personal token secrets have256 bits of browser-generated randomness; only SHA-256 digests persist. The read-only API verifies owner/project scopes, limits pagination and response size, and supports no write method. Server credentials remain in server environment settings and are sent only to the explicitly configured official Supabase host.

One existing atomic `discovery_rate_limits` store enforces Discovery, developer API and new product-action budgets; no second limiter store is added. Narrow wrappers derive the authenticated identity and fixed allowed action budgets. Publishing/feedback/invitation/team/credential issue use20/day; task workflows use20/day with at most20 tasks/run; Studio/Calendar/translation-note actions use50/day. Deleting public records or editable project history does not refund the quota. Idempotent successful replays do not spend another mutation budget.

Saved project documents and each workbench have256 KiB caps. Spaces permits20 links per collection and50 distinct links per workspace. Workbooks permit100 rows,12 columns and500 characters/cell, aggregate formulas only, cycle detection and an evaluation effort budget; CSV output neutralizes formula prefixes. No scripts, external spreadsheet links or arbitrary code execute.

AI features reuse authenticated EYRA's Responses API, streaming, server usage limits and write-permission defaults. Translation input is limited to8000 characters and requests can be cancelled/time out. Partial/cancelled translations cannot be saved as completed. Reviewed translation saving is an idempotent canonical Note operation. Interview feedback is ephemeral unless the user deliberately records content; no hiring or competence score is invented. Neither real-provider translation nor interview quality is verified by fixtures.

Operation retry metadata contains a UUID and source digest, not source content, and is scoped by account/project/tool/record in browser-tab storage. It survives a reload and clears at the account boundary. A changed source cannot silently reuse a pending operation. Confirmed result history remains inspectable; explicitly clearing pending metadata can permit another copy and requires confirmation. These are not immutable audit logs against an owner who edits their own JSON directly.

## Offline contract

Offline is opt-in, read-only and uses a separate12–200-character passphrase. AES-GCM uses a random salt/IV and PBKDF2-SHA256 with210000 iterations; identity is authenticated as associated data. The passphrase/key is not persisted. Snapshots contain at most500 recent Notes and100 projects, are owner-validated and capped at1 MiB. The encrypted wrapper alone is stored locally. Signing out/account changes clear the cache; the UI clears decrypted content when hidden or identities change. It is not a complete backup, key recovery system or offline editor.

The service worker caches only the static shell and same-origin `/assets/` build files, at most100 assets/20 MiB total/5 MiB each. API/Auth/Supabase/file bytes are excluded. Failed cache preparation is reported as failure. Static asset fallback ignores Origin Vary differences because the hashed build files are identical across callers. A real production-bundle browser test disables network, reloads `/offline`, unlocks the encrypted snapshot and locks it again.
