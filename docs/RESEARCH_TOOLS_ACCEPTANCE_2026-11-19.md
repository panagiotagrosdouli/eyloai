## Shared safeguards

- Results are generated by the actual application workflows, not placeholders. The export includes a bounded source manifest and an explicit notice that metadata **is not** independent full-text claim verification.
- The local research export is explicit and initiated by the user. It is **not** a cloud save or a promise of reproducible results. The PDF is a presentation artifact, not proof of the validity of its claims.
- Browser caches for Executive Briefing must be scoped to one authenticated owner and one session. Unscoped legacy `localStorage` keys are never read.
- Default paid-plan/AI feature gates remain intact. Do not bypass missing entitlements, live provider failure, unknown quota limits, or database RLS to make a test appear green.
- Some project and AI functions are assisted/experimental; their real usability must be tested with actual accounts and providers.

## Hosted release acceptance still required

1. Use a staging deployment with two independently provisioned users and explicit project access fixtures. No live customer records.
2. Each tool: perform a real authorized happy-path action and its error path; verify no phantom completed task or funding opportunity; verify export is correct and owner-only save.
3. Test 320/390/768/1024/1440px on mobile and desktop, keyboard focus, save retries, provider downtime, quota rejection and plan gating.
4. Have a qualified domain reviewer examine original sources and all material AI-generated claims; do not treat metadata or CID/ID checks as scientific validation.
5. Only after all gates pass: decide separate PR merge, exact production commit, release smoke and rollback readiness.

No database schema migration, production billing or live data mutation is included in this implementation PR.
